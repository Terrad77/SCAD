# v0.13.6 browser run history

History now includes browser execution records alongside the existing production revision inspection. The timeline is read-only: it offers no generation, approval, Resume, cancellation, deletion or recovery action. Overview remains the place to review the latest checkpoint.

GET /api/projects/:id/runs/history uses the existing local session/Host/Origin protection. A UUID cursor identifies the last record on the preceding page; pages contain ten runs sorted by immutable startedAt descending, then UUID descending for ties. Newer inserted records do not shift older pagination boundaries. Refresh rereads the first page. Cursor disappearance and inconsistent/latest-pointer changes return HISTORY_CHANGED rather than silently skipping data.

The reader validates the project and safe journal folder, allowlisted UUID run filenames, schemas, run ID/project identity and parseable start/update dates. Decision receipts are not interpreted as runs or revalidated as approval authority. Inspection refuses more than 1000 run files, 5000 folder entries, 1 MiB per run or 16 MiB of decoded run records. Corrupt, unreadable, linked or identity-mismatched records fail closed with an operator inspection error. No filesystem mutation occurs. The latest pointer is compared before/after inspection; individual event records can reflect different read times during execution, so this is not an atomic global audit snapshot.

The response omits server-owner and admission snapshot fields. It exposes parent IDs, missing-parent indication, recorded decision/note, checkpoint content/dependency/input signatures and up to the existing 100 saved events per run. A RUNNING record is ACTIVE only while the serving ProjectRuns instance owns it; otherwise it is UNVERIFIED. This never relaunches a job or infers current approval from a historical decision. Latest flags are observations at read time, not live polling guarantees.

The React panel uses native disclosures and English labels, persistent errors/retry, explicit refresh/older-page requests, disabled busy controls, status announcements and focus feedback. Late responses are ignored after project/section navigation unmounts the panel. Pagination deduplicates already displayed IDs. Event text and notes are escaped by React. Warm palette, bounded 940px reading width, wrapping identifiers, native text/SVG density and existing responsive rules remain; no dependency or motion added.

Scope excludes CLI-only execution history, full approval-ledger verification, reconstruction of events older than each run's retained 100 entries, automatic journal repair/archiving, publication packaging, cloud and Supabase. Actual checks and remaining limitations are recorded in workspace-preflight.md.

Chrome follow-up (2026-10-16): an explicit top-level GET / navigation may enter the workspace even when Chrome marks it cross-site, provided Fetch Metadata declares navigate/document/user ?1. Host and Origin checks still apply. This exception does not cover API paths, scripts, subframes, fetches or write methods. The subsequent same-origin session API checks are unchanged.
