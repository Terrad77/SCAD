# v0.14.3 — saved publication revision comparison

The Publication review now lets an author choose two saved revisions of one package and inspect changes before making a separate decision. It compares the audience question, title alternatives, summary, description, thumbnail brief and planned segments, including their ordered script-sentence references. Unsaved editor text and recovery copies are excluded.

Fields are compared exactly; whitespace and script-link order remain observable because signed content includes them. Titles and planned segments are matched by ordinal position, not semantic similarity. Inserting/reordering a field can therefore produce several positional changes. No word-level factual inference, quality score or semantic PASS is generated. Unchanged text does not establish support.

GET `/api/projects/:id/publication/compare?id=<package>&from=<revision>&to=<revision>&version=<journal-signature>` uses the existing session, Host, Origin and Fetch Metadata protections. Other methods are refused. UUID, revisions and journal signature are validated. The application rereads the validated journal against the observed signature before returning either version; changed journals return 409. Missing versions return 404. Project path validation and source verification reuse existing read paths. There are no writes, generation, approvals or full research payloads in this response.

Each side displays saved date, content/dependency identity, source audit, findings, current freshness and historical decision. Currently approved is true only for the latest CURRENT approved version; historical APPROVE never transfers to another version. Freshness is an observation at read time, not a permanent guarantee against concurrent source changes.

The deferred React panel owns selection, request lifecycle, filter and results. It ignores responses after unmount, clears results when selection changes and remounts after package/journal/project/freshness changes. Disabled editing/recovery states also disable comparison admission. Errors persist with retry; signature conflicts require explicit package reload. Native controls, disclosures and status focus use the existing BrandSans/warm-orange system. Before/after columns stack below 700px and show all text without invented truncation. Version and field counts are bounded by the existing package schemas.

Recovery, source materials, journal history and approval semantics remain unchanged. Export formats remain backward compatible. No comparison export, cross-package merge/rebase, upload, Gemini analysis or cloud storage is introduced.
