# v0.14 — Local publication packages

Publication is a separate English workspace section. Choose a verifiable completed browser run or completed production revision, prepare editorial packaging, review its references, record an explicit human decision and download Markdown/JSON. Generation and publishing are separate operations.

## Source boundary

A browser run requires all nine matching human checkpoint approvals. A production revision requires its matching final human approval. Selected production artifacts must be complete, current, independently auditable and consistent with their original manifest. Source resolution reads the original stored research and production artifacts. Historical versions whose research dependencies cannot be verified are excluded with an explanation.

Each package freezes its source, source proof and dependency signatures. Fields include an audience question, title alternatives, supported summary, description, thumbnail brief and planned segments. Links refer to existing script sentences and retain shots, claims, evidence, source records, knowledge labels, hypotheses, uncertainties, contradictions and constraint treatments. Segments have no invented final timestamps.

## Persistence and review

`publication/journal.json` stores signed package versions, decisions and request receipts in one atomic replacement under the shared project write coordinator. It never writes research, reasoning, production memory or the pipeline approval ledger. Exact request replay survives later edits; conflicting request identity and optimistic version conflicts are refused. This provides retry/crash recovery through atomic replacement, not a certified power-loss durability guarantee.

Saving creates a new version without inherited consent. Approval binds the exact package content and dependency signatures, requires the latest CURRENT version and refuses mechanical FAIL findings. Reject requires a reason. Historical decisions remain visible. Dependency changes mark packages STALE without regenerating or rewriting them; unavailable verification marks them UNVERIFIED. Selecting a different source requires a new package.

Reference checks validate existing links and evidence support mechanically. Semantic support always remains UNKNOWN. Lexical promise warnings are hints, can flag negated wording and do not establish factual correctness. Human packaging approval does not override the source audit or certify the film's factual claims. Only the latest CURRENT approved version exports as an approved packaging copy; older or changed versions export as review copies.

## Limits and local API

Up to 100 package versions and 500 operation receipts per project; journal maximum 16 MiB. Source capture and selectable-source payloads are bounded. Each linked field permits at most 20 sentence references. Large or corrupt data is refused with a persistent explanation.

GET/POST `/api/projects/:id/publication` and GET `/publication/export` retain session authorization, local Origin, Host and Fetch Metadata protections. Publication requests allow 128 KiB; other mutation limits remain unchanged. Paths and symlinks are checked. Export reads a bounded snapshot and includes its signatures; subsequent source changes can invalidate that observation.

The editor loads on demand as a hashed ES module. Initial viewer and shared modules total 288560 raw bytes (baseline 287971, +589); optional editor 13436 bytes. Static chunk paths accept a strict filename pattern. No new runtime dependencies, fonts, raster assets or motion.

## Exclusions

No YouTube upload, Gemini analysis, Supabase/cloud, final timecodes/subtitles, semantic factual certification, automatic regeneration or automatic approval.
