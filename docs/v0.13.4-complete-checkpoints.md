# v0.13.4 - Complete browser checkpoints

The local Overview workflow supports review, Approve/Reject and explicit Resume for all nine documentary stages: Research, Claims, Hypotheses, Fact check, Epistemic preparation, Reasoning context, Narrative, Visual plan and Self-check. CLI remains available for recovery and separate governed production revisions/issues. This completes the primary project-to-script browser workflow; it does not implement every optional extension proposed elsewhere.

## Ownership and signatures

Pipeline supplies the actual StageProposal to its approval gate. The browser run saves that proposal's artifact/dependency signatures with the project title/question identity. Other ApprovalGate implementations remain compatible with the optional third argument.

Review captures raw candidate and upstream JSON in pipeline order, validates each without reconstructing signed content, and checks every upstream human approval against its artifact and preceding dependencies. It rereads captured bytes around the immutable viewer snapshot. Missing, unsafe, corrupt or oversized material fails closed; combined candidate/upstream review is limited to 32MiB. Epistemic preparation has a full structural checkpoint schema. ReasoningContext additionally requires its internal integrity signature to validate.

The existing protected /review and /resume routes, shared writer ownership and durable receipts are reused. Receipt authority, decision ID, action, body, stage, run ID and completion digest must agree. A receipt from another stage cannot authorize a decision or continuation. Original v0.13.2 Research receipts remain valid. Historical decisions never approve changed content; pending decisions require replay of the original immutable request, and interrupted RUNNING jobs do not auto-restart.

Resume retains the parent's journal and admits a linked child. Previously approved stages are reused by the existing Pipeline rules; the next unapproved candidate is saved and execution stops. No human approval is fabricated for real projects. Reject preserves the candidate and rationale and grants no continuation. No force, modification, regeneration or automatic step chaining is added.

## Interface

The shared CheckpointReviewPanel retains the existing typography, semantic colors, bounded reading width, native disclosures and 44px controls. It shows an English stage label, readable summary, full raw candidate, full upstream materials and checkpoint identities. Research retains source/evidence inspection with HTTP(S)-only links. Narrative summary preserves sentence IDs and knowledge labels. Visual summary includes shot IDs, visual type, descriptions and narration. Full artifacts remain available for all references and provenance.

Self-check displays the saved verdict and findings. Accepting its checkpoint does not convert WARN/FAIL/UNKNOWN into PASS, resolve findings or authorize external publication. After the final explicit Resume, the existing exporter writes local artifacts; completion is distinct from audit certification.

Validation, busy/disabled controls, persistent failure, exact-request retry, draft-discard reload and focus transfer follow v0.13.3. Changed content disables Resume and is revalidated server-side regardless of UI state. No raster assets, remote fonts, animation or dependencies were introduced. The external untracked brandsans package remains untouched and is excluded from SCAD lint/format scope.

## Boundaries

Supabase, accounts, media generation, YouTube upload/analysis, browser editing/regeneration, browser production revision/issue commands, cancellation and arbitrary interrupted-job recovery are separate work. Human editorial decisions on actual projects remain user actions. Verification and browser limitations are recorded in workspace-preflight.md; remaining work is tracked in TODO-completion.md.
