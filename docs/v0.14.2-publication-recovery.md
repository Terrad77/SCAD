# v0.14.2 — browser publication recovery

The editor keeps a bounded localStorage copy of the unsaved document and decision note on the same browser origin, after each edit. The copy is not a package revision, a decision, or an approval. Browser storage may be disabled, cleared, full, or inaccessible; the editor reports write failures and remains usable. The copy is readable by other scripts on the same origin and anyone with access to the browser profile. Do not use shared profiles for sensitive drafts.

On reopening, restore requires the same project and journal versions, package revision, source identity, proof and dependency signatures. Otherwise the user may copy the old text manually or delete the copy. No source or server data is modified by recovery. A saved or explicitly discarded draft removes its own copy. The recovery check avoids overwriting another observed copy, but localStorage does not provide a transactional lock across tabs; edit one project in one tab at a time. A request interrupted after server commit may already have succeeded; inspect the saved state rather than assuming failure. Browser copies cannot guarantee survival of browser termination, power loss, storage eviction, or device failure.

Native close/reload warnings, slow transport, real devices and screen-reader interaction require manual verification; automated storage tests do not establish these behaviors.
