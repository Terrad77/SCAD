# v0.12 — shared project write ownership

Baseline: main at 553182d. This is the first implemented v0.12 increment, not the complete governed command/review UI described in v0.11-local-workspace-design.md.

A stable root-level .scad-writes directory holds per-project ownership directories. The key is a hash of normalized case-folded project ID so Windows case aliases compete for one owner. Atomic directory creation is the acquisition primitive on a local filesystem. The owner record includes a unique nonce, project, action and PID for diagnostics. PID is not proof that ownership can be reclaimed.

All public CLI commands that can generate, initialize, mutate, verify or export project files hold this ownership for the entire awaited operation, including interactive checkpoints and publication. Pure project readers remain independent. HTTP Trash and Restore use the same coordinator; their old process-local busy guard is secondary. Locks remain outside moved project directories. Snapshot and publication checks for Trash occur under ownership. Unsafe names, link directories and directories outside the resolved root are rejected. Different projects may have different owners.

Normal completion and domain exceptions release only the matching ownership nonce. Crash, missing/corrupt metadata and changed ownership fail closed. There is no automatic timeout, PID-based stealing, HTTP force-unlock or concurrent recovery promise. An interrupted operation requires operator investigation: stop all SCAD writers, inspect .scad-writes/<hash>/owner.json and the project domain journal, verify it belongs to the intended project, remove only that confirmed ownership directory, then resume through the existing CLI journal-aware command. Do not reset locks while any writer might still be running. The recovery UI is a future increment.

Supported scope: one local machine and local filesystem, upgraded CLI/server entrypoints. Network shares, old binaries, manual external edits and direct engine calls that bypass application entrypoints are not covered. Restart the server and all CLI processes after upgrading. This coordinator does not replace scoped memory, dependency signatures, approvals or publication recovery.

UI now identifies the workspace as v0.12. Package semver is unchanged because numbered architectural increments have historically differed from package version. Further functional scope (project creation versus run/review UI) awaits user selection. No generation endpoint or invented approval capability is added here.
